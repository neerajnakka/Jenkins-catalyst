Shared Libraries — stop repeating yourself

Goal: move duplicated pipeline logic into one versioned, testable library that both apps use. This is the single biggest signal of a senior Jenkins engineer.

14.1 The problem and the fix

By now nodejs-app/Jenkinsfile and python-app/Jenkinsfile are 90% identical: checkout, build, test, docker build, push, notify. If you need to change the tag strategy you must edit every file — and you will forget one. A shared library is a Git repo of Groovy code that pipelines import.

treejenkins-shared-library/ (its own Git repo)
jenkins-shared-library/
├── vars/                       <-- every file becomes a GLOBAL STEP by filename
│   ├── buildAndPushImage.groovy      -> step: buildAndPushImage(...)
│   ├── runTests.groovy               -> step: runTests(...)
│   ├── notifyBuild.groovy            -> step: notifyBuild(...)
│   └── standardPipeline.groovy       -> step: standardPipeline { ... }   (full template)
├── src/
│   └── com/example/ci/
│       └── Docker.groovy       <-- real Groovy classes: import com.example.ci.Docker
└── resources/
    └── scripts/deploy.sh       <-- non-Groovy files, loaded with libraryResource
DirectoryBecomesUse for

14.3 Writing your first steps

groovyvars/notifyBuild.groovy — one file = one step
// vars/notifyBuild.groovy
// Called from a pipeline as:  notifyBuild('SUCCESS')
def call(String buildStatus = 'STARTED') {
    def color  = buildStatus == 'SUCCESS'  ? 'good'    :
                 buildStatus == 'UNSTABLE' ? 'warning' :
                 buildStatus == 'FAILURE'  ? 'danger'  : 'good'

    def subject = "${buildStatus}: ${env.JOB_NAME} #${env.BUILD_NUMBER}"
    def summary = "${subject}\nCommit: ${env.GIT_COMMIT ?: 'n/a'}\nMore: ${env.BUILD_URL}"

    echo summary                          // always visible in the console

    // Send to Slack only if the plugin + credential exist (safe on any controller)
    try {
        withCredentials([string(credentialsId: 'slack-token', variable: 'SLACK_TOKEN')]) {
            slackSend channel: '#ci', color: color, message: summary, tokenCredentialId: 'slack-bot'
        }
    } catch (err) {
        echo "Slack notification skipped: ${err.message}"
    }
}
groovyvars/buildAndPushImage.groovy
// vars/buildAndPushImage.groovy
// Usage:  buildAndPushImage(image: 'user/app', tag: env.GIT_SHA, context: 'nodejs-app')
def call(Map config = [:]) {
    def image   = config.image   ?: error('buildAndPushImage: `image` is required')
    def tag     = config.tag     ?: env.GIT_SHA ?: env.BUILD_NUMBER
    def context = config.context ?: '.'
    def pushLatest = config.get('pushLatest', false)
    def extraTags  = config.get('extraTags', [])

    dir(context) {
        def img = docker.build("${image}:${tag}", '--pull .')

        docker.withRegistry('https://index.docker.io/v1/', 'dockerhub-creds') {
            img.push(tag)
            extraTags.each { t -> img.push(t) }
            if (pushLatest) { img.push('latest') }
        }

        def digest = sh(script: "docker inspect --format='{{index .RepoDigests 0}}' ${image}:${tag}",
                        returnStdout: true).trim()
        echo "Pushed ${digest}"
        return "${image}:${tag}"
    }
}
groovyvars/runTests.groovy — one step for both ecosystems
// vars/runTests.groovy
// Usage:  runTests(type: 'node', minCoverage: 70)
//         runTests(type: 'python', minCoverage: 80)
def call(Map config = [:]) {
    def type = config.type ?: error('runTests: `type` must be "node" or "python"')
    def min  = config.get('minCoverage', 70)

    try {
        if (type == 'node') {
            sh label: 'jest', script: 'npm run test:junit'
        } else if (type == 'python') {
            sh label: 'pytest', script: ". venv/bin/activate && pytest --cov-fail-under=${min}"
        } else {
            error "Unknown project type: ${type}"
        }
    } finally {
        // always publish, even if the tests failed -- that's the whole point
        junit testResults: 'reports/junit.xml', allowEmptyResults: true
    }
}

14.4 The big one: a full pipeline template

groovyvars/standardPipeline.groovy — a declarative wrapper
// vars/standardPipeline.groovy
// A "template method": the library owns the shape, each app fills in the details.
//
// Usage from a Jenkinsfile:
//   standardPipeline {
//       type      = 'node'            // or 'python'
//       image     = 'user/nodejs-app'
//       context   = 'nodejs-app'
//       minCoverage = 70
//   }
def call(Map config, Closure body = null) {
    def type    = config.type ?: 'node'
    def image   = config.image ?: error('standardPipeline: `image` required')
    def context = config.context ?: '.'
    def min     = config.get('minCoverage', 70)
    def agent   = type == 'node' ? 'node:20-alpine' : 'python:3.12-slim'

    pipeline {
        agent none

        options {
            timestamps()
            timeout(time: 40, unit: 'MINUTES')
            buildDiscarder(logRotator(numToKeepStr: '50', artifactNumToKeepStr: '10'))
            disableConcurrentBuilds()
        }

        stages {
            stage('Checkout') {
                agent { label 'linux' }
                steps {
                    script {
                        checkout scm
                        env.GIT_SHA = sh(script: 'git rev-parse --short HEAD', returnStdout: true).trim()
                        currentBuild.description = env.GIT_SHA
                    }
                }
            }

            stage('Build') {
                agent { docker { image "${agent}"; reuseNode true } }
                steps {
                    dir(context) {
                        sh type == 'node' ? 'npm ci'
                                          : 'python -m venv venv && . venv/bin/activate && pip install -r requirements-dev.txt'
                    }
                }
            }

            stage('Test') {
                agent { docker { image "${agent}"; reuseNode true } }
                steps {
                    dir(context) { runTests(type: type, minCoverage: min) }
                }
            }

            stage('Package & Push') {
                agent { label 'docker' }
                when { anyOf { branch 'main'; branch 'develop' } }
                steps {
                    buildAndPushImage(image: image, tag: env.GIT_SHA, context: context,
                                      pushLatest: (env.BRANCH_NAME == 'main'),
                                      extraTags: [env.BUILD_NUMBER])
                }
            }
        }

        post {
            always  { script { notifyBuild(currentBuild.currentResult) } }
            cleanup { node('linux') { cleanWs() } }
        }
    }
}
groovyThe Jenkinsfiles become tiny
// nodejs-app/Jenkinsfile
@Library('jenkins-shared-library@main') _
standardPipeline {
    type        = 'node'
    image       = '<user>/nodejs-app'
    context     = 'nodejs-app'
    minCoverage = 70
}

// python-app/Jenkinsfile
@Library('jenkins-shared-library@main') _
standardPipeline {
    type        = 'python'
    image       = '<user>/python-app'
    context     = 'python-app'
    minCoverage = 70
}
🧠Why the trailing underscore? @Library('name') _ is the correct syntax when you are not importing a class — the bare _ is a placeholder for "no import statement". Without it Groovy parses the annotation incorrectly. Also note: @Library must be on its own line above everything else (only comments may precede it).

14.5 Versioning & safety

PracticeWhy
Pin the version: @Library('lib@v1.4.0') _Branches move. A tag gives reproducible builds; use @main only in development.
Test library changes on a branch firstPoint one test pipeline at @feature-branch before merging to main.
Unit-test with JenkinsPipelineUnitA JUnit-based framework that runs your vars against a mocked Jenkins. Real teams do this.
Keep vars/ thinBusiness logic belongs in src/ classes, which are far easier to unit test.
Remember the trust boundaryLibrary code runs outside the Groovy sandbox — it can do anything on the controller. Review library PRs like production code, and restrict who can push to the library repo.

14.7 💬 Interview Q&A

Q1What is a Jenkins shared library and why use one?
A Git repository of Groovy code that pipelines import with @Library('name@version') _. Files in vars/ become global steps, src/ holds classes, and resources/ holds non-Groovy files. It removes duplication across dozens of Jenkinsfiles, so a change to tagging, notifications or scanning is made once, reviewed once, and adopted everywhere.
Q2How do you version shared libraries safely?
Tag releases and reference a tag (@v1.4.0) from production pipelines, so a change to main can't break them. New versions are validated by pointing a test pipeline at the branch first, and by unit tests with JenkinsPipelineUnit.
Q3What are the security implications?
Shared library code runs outside the Groovy sandbox with full controller privileges, so anyone who can merge to the library repo effectively has admin on Jenkins. I'd restrict write access, require code review, and keep secrets handling in the credentials store rather than in library code.
Q4How do you test a shared library?
With JenkinsPipelineUnit — a JUnit framework that mocks the Jenkins runtime so I can assert that steps were called with the right arguments. I keep logic in src/ classes where possible, because plain Groovy classes are much easier to unit test than pipeline scripts.

14.8 Under the hood — how a library is loaded

  1. Resolution. The library name (jenkins-shared-library) is looked up in Global Pipeline Libraries → the SCM is checked out to $JENKINS_HOME/workflow-libs/<name>/ at the requested version.
  2. Loading. Files in vars/ are compiled into global CPS-transformed scripts: vars/foo.groovy with a call() method becomes the step foo(...). Classes in src/ are loaded by the Groovy classloader and available via import.
  3. Sandbox. Library code runs outside the Groovy sandbox — it has full controller privileges. That's the security trade-off for its power.
  4. Caching. The checkout is cached per version; changing @main means new commits are pulled on the next run.
🚨Three consequences you must internalise
  • Library code can do anything — restrict who can merge to it.
  • @main means a bad merge breaks every consumer at once. Pin tags in production.
  • Steps defined in vars/ run in CPS: keep them thin and put heavy logic in src/.

14.9 Writing a library step properly

groovyvars/deployCompose.groovy — docs, defaults, validation, return value
// vars/deployCompose.groovy
//
// Deploy a compose stack over SSH.
//
//   deployCompose(host: 'staging.example.com',
//                 stackPath: '/opt/nodejs-app',
//                 image: 'user/nodejs-app',
//                 tag: env.GIT_SHA,
//                 port: 3000,
//                 healthPath: '/health')
//
def call(Map config) {
    // ---- 1. validate inputs loudly -------------------------------------
    ['host', 'stackPath', 'image', 'tag'].each { k ->
        if (!config[k]) { error "deployCompose: '${k}' is required" }
    }
    def port       = config.get('port', 3000)
    def healthPath = config.get('healthPath', '/health')
    def credId     = config.get('credentialsId', 'deploy-key')
    def user       = config.get('user', 'ubuntu')

    // ---- 2. do the work -------------------------------------------------
    sshagent(credentials: [credId]) {
        sh """
            ssh -o StrictHostKeyChecking=no ${user}@${config.host} '
                set -e
                cd ${config.stackPath}
                export IMAGE_REPO=${config.image} IMAGE_TAG=${config.tag}
                docker compose pull
                docker compose up -d --remove-orphans
                curl -fsS --retry 20 --retry-delay 3 http://localhost:${port}${healthPath}
            '
        """
    }

    // ---- 3. return something useful ------------------------------------
    return "${config.image}:${config.tag}@${config.host}"
}
groovysrc/com/example/ci/DeployTarget.groovy — pure logic, easy to test
package com.example.ci

/** Value object describing where an app can be deployed. */
class DeployTarget implements Serializable {
    String host
    String path
    String user = 'ubuntu'
    int    port
    String healthPath = '/health'

    String composeCommand(String repo, String tag) {
        "cd ${path} && IMAGE_REPO=${repo} IMAGE_TAG=${tag} docker compose up -d --remove-orphans"
    }

    String healthUrl() { "http://localhost:${port}${healthPath}" }

    static DeployTarget nodejs(String envName) {
        envName == 'prod'
            ? new DeployTarget(host: 'prod.example.com',   path: '/opt/nodejs-app', port: 3000)
            : new DeployTarget(host: 'staging.example.com', path: '/opt/nodejs-app', port: 3000)
    }
}

}
groovytest/com/example/RunTestsSpec.groovy
package com.example

import com.lesfurets.jenkins.unit.BasePipelineTest
import org.junit.Before
import org.junit.Test

class RunTestsSpec extends BasePipelineTest {

    @Override @Before
    void setUp() {
        super.setUp()
        binding.setVariable('env', [BRANCH_NAME: 'main', BUILD_NUMBER: '7'])
    }

    @Test void 'runs npm test for node projects'() {
        def script = loadScript('vars/runTests.groovy')
        script.call(type: 'node', minCoverage: 70)
        assert helper.callStack.findAll { it.methodName == 'sh' }
                .any { it.toString().contains('npm run test:junit') }
        printCallStack()
    }

    @Test void 'rejects an unknown project type'() {
        def script = loadScript('vars/runTests.groovy')
        try {
            script.call(type: 'ruby')
            assert false : 'should have thrown'
        } catch (Exception e) {
            assert e.message.contains('Unknown project type')
        }
    }
}
💡Worth ten minutes of your time Being able to say "our shared library has unit tests that run in CI" is a genuine differentiator. Very few Jenkins engineers do it, and interviewers notice immediately.

14.11 More interview Q&A

Q5How do you structure a shared library for a large organisation?
vars/ for the thin, stable, documented step API; src/ for the real logic as testable classes; resources/ for scripts and templates. Semantic-versioned releases pinned by consumers, unit tests with JenkinsPipelineUnit, and a CHANGELOG. Breaking changes go in a new major version — never silently on main.
Q6How do you roll out a breaking library change?
Add the new version alongside the old (a new step name or a new major tag), migrate a pilot team first, keep both working for one release cycle, then update everyone and remove the old path. Because consumers pin versions, the migration is a coordinated set of pull requests rather than an outage.
Q7Can a shared library call another shared library?
Yes — a library can depend on another via its own @Library annotation or through configured library dependencies. I keep the dependency graph shallow (one or two levels) because deep chains are hard to reason about and to version.
Q8Why does my library step not see env or sh?
Steps in vars/ run as CPS scripts that delegate to the surrounding pipeline, so they must be called from inside a pipeline context. Pure classes in src/ have no pipeline context at all — pass what they need as arguments, which is also exactly what makes them testable.
Q9How do you document a shared library?
A README.md in the library repo plus a Javadoc-style comment block at the top of every vars/ file showing usage and parameters. Jenkins also renders a sibling vars/<step>.txt as inline help in the Snippet Generator, so I add one for each step.
