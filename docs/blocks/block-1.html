Goal: own a real Jenkins controller and be able to name every menu in it. A pipeline you can't see running is a pipeline you can't debug.

1.1 What Jenkins actually is — the 80% mental model

Jenkins is an automation server: a Java application that runs jobs when something tells it to. Four words carry most of the interview:

🧠 Controller (old name: master)

The brain. Stores config, plugins, credentials, build history; serves the UI on port 8080. In real companies it runs zero builds — it only orchestrates.

💪 Agent (old name: slave)

The muscle. A machine (VM, container, pod) that connects to the controller and executes steps. Agents carry labels — linux, docker, node20 — so you can route work.

🎛️ Executor

A slot. Two executors = two concurrent builds. "Pending — waiting for next available executor" simply means every slot is busy.

📄 Jenkinsfile

Your pipeline as code, committed beside the app. Versioned, reviewed in PRs, reusable. The heart of everything from Block 2 onward.

💡Pipeline as Code — say this out loud in interviews Before 2016 you configured jobs by clicking (Freestyle). That config lived only inside Jenkins — lost in a crash, impossible to review, impossible to reuse. A Jenkinsfile moves the configuration into Git: versioned, reviewable, diffable, and enough to rebuild your whole CI from scratch. That shift is called Pipeline as Code, and it's why declarative pipeline syntax is the single most-asked Jenkins skill today.

1.3 The complete install script

SSH in as ubuntu and run this. The comments are the lesson — read them. The file lives in your repo at jenkins/ec2-install.sh.

bashjenkins/ec2-install.sh
#!/usr/bin/env bash
# =============================================================
#  jenkins/ec2-install.sh -- Block 1
#  Fresh Ubuntu 24.04 LTS EC2  ->  Jenkins LTS + Docker engine
#  Usage:  bash ec2-install.sh
# =============================================================
set -euo pipefail                 # exit on error, unset var, pipe failure

echo "### 1/7  Base packages + system update"
sudo apt-get update -y && sudo apt-get upgrade -y
sudo apt-get install -y fontconfig ca-certificates curl gnupg git unzip jq

echo "### 2/7  Java 21  (Jenkins LTS 2.4xx supports Java 17 and 21)"
sudo apt-get install -y openjdk-21-jre-headless
java -version                     # MUST print something like "openjdk 21.0.x"

echo "### 3/7  Official Jenkins apt repository (keyring style, not apt-key)"
sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key \
     -o /etc/apt/keyrings/jenkins-keyring.asc
echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/" \
  | sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null
sudo apt-get update -y

echo "### 4/7  Install Jenkins LTS and enable it at boot"
sudo apt-get install -y jenkins
sudo systemctl enable --now jenkins
sleep 25
sudo systemctl status jenkins --no-pager | head -5

echo "### 5/7  Docker engine (needed from Block 9: build & push)"
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update -y
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
                        docker-buildx-plugin docker-compose-plugin

echo "### 6/7  Let the 'jenkins' user build docker images (LEARNING SHORTCUT)"
sudo usermod -aG docker jenkins
sudo tee /etc/sudoers.d/jenkins > /dev/null <<'SUDO'
jenkins ALL=(ALL) NOPASSWD:ALL
SUDO
sudo chmod 0440 /etc/sudoers.d/jenkins

echo "### 7/7  Restart so the new group membership is picked up"
sudo systemctl restart docker
sudo systemctl restart jenkins
sleep 20
echo "=========================================================="
echo " Unlock password  ->  paste this in the browser:"
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
echo "=========================================================="
echo " Open:  http://$(curl -s http://169.254.169.254/latest/meta-data/public-ipv4):8080"
🚨Read this before you run step 6/7 jenkins ALL=(ALL) NOPASSWD:ALL lets the Jenkins user run anything as root without a password. Fine on a throwaway learning box; career-ending in production. Same for usermod -aG docker jenkins — docker group membership is effectively root. Block 9 covers the real options (Docker-in-Docker, rootless BuildKit, Kaniko, agent isolation) and Block 12 locks the controller down with RBAC.
bashverify.sh — prove it works
# Is Jenkins alive?
sudo systemctl is-active jenkins                 # -> active
sudo ss -tlnp | grep 8080                        # -> LISTEN  java

# Can the jenkins user use docker? (the #1 thing that breaks in Block 9)
sudo -u jenkins docker info --format '{{.ServerVersion}}'
sudo -u jenkins docker run --rm hello-world      # must print "Hello from Docker!"

# Where to look when it isn't
sudo journalctl -u jenkins -n 100 --no-pager
sudo tail -f /var/log/jenkins/jenkins.log

# Toolchains for our two apps
sudo apt-get install -y nodejs npm python3 python3-pip python3-venv
node -v && npm -v && python3 -V

1.4 First boot: the setup wizard, click by click

  1. Unlock Jenkins. Open http://<EC2-PUBLIC-IP>:8080 and paste the password from /var/lib/jenkins/secrets/initialAdminPassword. It exists only until setup finishes — that is the security model: prove you have filesystem access to the box.
  2. Customize Jenkins. Choose Select plugins to install (not "Install suggested") so you know exactly what you own. Use the list below.
  3. Create the first admin user. Never keep admin with the random password — Block 12 builds RBAC on top of your account.
  4. Instance Configuration. Leave the Jenkins URL as the public IP. If you later attach a domain, change it in Manage Jenkins → System → Jenkins Location.
  5. Start using Jenkins. You now have a controller.

  • + echo … comes from the -xe flags: x prints each command (trace), e exits at the first failure. That's why one failing command stops the build.

⚠️Why we abandon Freestyle after this Freestyle config lives only in the Jenkins UI: no history, no review, no reuse, one server = one copy, and complex logic becomes a wall of checkboxes. It survives for tiny maintenance jobs, but every interview question assumes pipelines. From Block 2 we write Jenkinsfiles and never look back.

1.8 Linux users, groups & permissions (interview favourite)

Jenkins runs as the OS user jenkins. Almost every beginner error is a permissions error wearing a disguise.

CommandMeaning
sudo -u jenkins <cmd>Run as the jenkins user — the #1 debugging move. If it fails here, it will fail in the pipeline.
id jenkinsShow uid/gid/groups. Is docker in the list?
sudo usermod -aG docker jenkinsAdd jenkins to docker. -a = append — without it you wipe the other groups.
sudo chown -R jenkins:jenkins /pathFix "Permission denied" on a directory.
chmod 600 ~/.ssh/id_ed25519SSH keys must be owner-readable only or ssh refuses them. Critical in Blocks 4 and 13.
ls -l /var/run/docker.sockShould be root:docker. If jenkins isn't in that group → the classic "permission denied while trying to connect to the Docker daemon socket".
🎤Interview question you will get Q. Your pipeline says "permission denied" but the identical command works in your terminal. Why?
Because I ran it as ubuntu and Jenkins runs it as jenkins. I reproduce exactly what Jenkins sees with sudo -u jenkins <command>, then fix ownership or group membership — for example adding jenkins to the docker group and restarting the service so the new group is loaded.

1.10 💬 Interview Q&A

Q1Difference between Jenkins controller and agent?
The controller stores configuration, plugins, credentials and history, and decides what runs where. Agents execute the actual steps. Best practice is to set the controller's executors to 0 so a heavy build can never take the UI down (Block 13).
Q2What is an executor?
A slot that runs one build at a time. Two executors = two concurrent builds on that node. "Waiting for next available executor" means all slots are busy — fix by adding executors on that agent or more agents sharing the label.
Q3Where does Jenkins store its data?
In JENKINS_HOME, default /var/lib/jenkins: jobs, workspaces, plugins, secrets, nodes and config.xml. Backing up that directory plus your Jenkinsfiles (which live in Git) is a complete disaster-recovery plan.
Q4Freestyle vs Pipeline?
Freestyle is UI-configured and not version-controlled; hard to review or reuse. Pipeline is code in a Jenkinsfile: stored in Git, reviewable, reusable via shared libraries, and supports parallel, retry, approvals and Docker agents. Pipeline is the standard.
Q5Which Java version does modern Jenkins need?
Jenkins 2.463+ requires Java 17 or 21 (21 recommended); older 2.3xx ran on Java 11. Verify with Manage Jenkins → System Information → java.version.

1.12 Under the hood — what happens when Jenkins boots

Knowing the startup sequence turns "Jenkins won't start" from panic into a three-minute diagnosis.

  1. systemd launches the JVM. /usr/lib/systemd/system/jenkins.service runs the WAR with the options in /etc/default/jenkins. That file is where JAVA_ARGS lives — heap size, timezone, CSP settings.
  2. JENKINS_HOME is resolved (default /var/lib/jenkins). If it doesn't exist, Jenkins creates it and runs the setup wizard.
  3. The secret store is unlocked with secrets/master.key. If the key is missing, Jenkins generates a fresh one — which silently makes every existing credential undecryptable.
  4. Plugins load from plugins/*.jpi in dependency order. One incompatible plugin can stall the whole boot, which is why you update plugins before upgrading core.
  5. Configuration is deserialised. Jenkins persists objects as XML with XStream: config.xml is literally a serialised Java object graph. That's why hand-editing works, and why a malformed edit stops the boot.
  6. Agents reconnect over the remoting protocol (inbound TCP or SSH) and the queue is rebuilt from disk.
bash/etc/default/jenkins — the lines that matter
# Heap + headless + timezone. 2-4 GB on a real controller.
JAVA_ARGS="-Xmx2048m -Djava.awt.headless=true -Duser.timezone=Asia/Kolkata"
JENKINS_HOME=/var/lib/jenkins
JENKINS_ARGS="--httpListenAddress=127.0.0.1 --httpPort=8080"   # once a proxy is in front

1.14 Production notes — TLS and a reverse proxy

Raw :8080 is fine while learning. The moment anyone else uses the controller, terminate TLS and hide the port:

nginx/etc/nginx/sites-available/jenkins
upstream jenkins {
    keepalive 32;
    server 127.0.0.1:8080;                       # Jenkins stays on localhost
}
server {
    listen 80;
    server_name jenkins.example.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl http2;
    server_name jenkins.example.com;

    ssl_certificate     /etc/letsencrypt/live/jenkins.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/jenkins.example.com/privkey.pem;

    proxy_set_header Host              $host;               # Jenkins needs its public URL
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    location / {
        proxy_pass         http://jenkins;
        proxy_read_timeout 300s;      # long console streams
        proxy_buffering    off;       # live console output
    }
}
bashCertificate + switchover
sudo apt-get install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d jenkins.example.com
# add --httpListenAddress=127.0.0.1 to JENKINS_ARGS, then:
sudo systemctl restart jenkins nginx
# Manage Jenkins -> System -> Jenkins Location -> https://jenkins.example.com/
⚠️Two proxy gotchas that cost hours If Jenkins Location URL still says http://…:8080, GitHub webhooks and agent JNLP files point at the wrong address. And without proxy_buffering off the live console log appears frozen until the build ends.

1.15 More interview Q&A

Q6How do you put Jenkins behind HTTPS?
Run Nginx as a reverse proxy with a Let's Encrypt certificate, bind Jenkins to 127.0.0.1:8080, forward X-Forwarded-*, disable proxy buffering so the console streams live, and update the Jenkins URL in the system configuration so webhooks and agent connections use the public HTTPS address.
Q7How does Jenkins persist configuration?
Objects are serialised to XML with XStream — one config.xml per job and one global file. Loading is deserialisation, so "Reload Configuration from Disk" re-reads those files. It also means a corrupt file stops the boot, which is why I keep backups and manage important settings with JCasC.
Q8What JVM tuning do you apply to a controller?
Set -Xmx to 2–4 GB, keep the controller's executor count at 0 so builds don't share that heap, and monitor GC and old-gen usage. Most "Jenkins is slow" incidents are GC pressure caused by running builds on the controller.
Q9Which ports does Jenkins use?
8080 HTTP, 443 via proxy, 50000 for inbound JNLP agents; SSH agents are contacted outbound on 22. In production I expose only 443 and keep 8080 and 50000 on localhost or a private network.
