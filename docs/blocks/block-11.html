Block 11 · Real engineering

post{} mastery — cleanup, artifacts & signals

Goal: make every build finish responsibly: reports published, artifacts kept, workspaces cleaned, and the right people told the right thing.

11.1 Every condition, and the order they run in

OrderConditionFires whenPut here
1alwaysEvery runPublish tests & coverage, record results
2changedResult differs from the previous build"Status changed" notices
3abortedCancelled (manual or timeout)Release locks/resources
4regressionWas succeeding, now failingEscalate: "you broke main"
5fixedWas failing, now succeedingClose the incident, celebrate
6success / failure / unstable / unsuccessfulResult-specificNotifications, tagging, rollbacks
7cleanupAlways, and lastDelete temp files, stop containers, prune images
⚠️Two things beginners get wrong
  • All matching conditions run — they are not else if. A green build runs always and success.
  • cleanup runs after everything, even if a step inside always throws. Anything that must not be skipped goes there.

11.2 post at stage level too

groovyPer-stage post — surgical reactions
stage('Container Smoke Test') {
    steps { script { app.inside('-p 3100:3000') { sh 'curl -fsS localhost:3100/health' } } }
    post {
        failure {
            // only this stage failed -> give the on-call engineer the container logs
            sh 'docker logs $(docker ps -lq) || true'
            archiveArtifacts artifacts: 'container.log', allowEmptyArchive: true
        }
    }
}

11.3 The currentBuild object

groovyEverything useful about "this build"
post {
    always {
        script {
            echo "result        : ${currentBuild.currentResult}"   // SUCCESS / FAILURE / UNSTABLE / ABORTED
            echo "final result  : ${currentBuild.result}"          // null until set
            echo "duration      : ${currentBuild.durationString}"
            echo "url           : ${currentBuild.absoluteUrl}"
            echo "previous      : ${currentBuild.previousBuild?.result}"
            echo "changed files : ${currentBuild.changeSets}"      // who broke it, and which files

            // make the build history readable at a glance
            currentBuild.description = "${params.ENV ?: 'dev'} · ${env.GIT_SHA}"
            currentBuild.displayName = "#${env.BUILD_NUMBER} ${env.GIT_SHA}"
        }
    }
    failure {
        script {
            def culprits = currentBuild.changeSets.collectMany { it.items.collect { it.author.fullName } }.unique()
            echo "Notify: ${culprits.join(', ')}"
        }
    }
}

11.4 Workspace cleanup — the disk discipline

groovyThree levels of tidiness
post {
    cleanup {
        // 1. Fast: wipe the workspace (requires the Workspace Cleanup plugin)
        cleanWs()

        // 2. Targeted: keep the workspace, remove the heavy stuff
        // deleteDir()                        // nuke everything
        // sh 'rm -rf nodejs-app/venv'        // just the venv

        // 3. Reclaim Docker disk (the biggest offender on a CI box)
        sh '''
            docker image prune -f || true
            docker container prune -f || true
            docker builder prune -f || true
        '''
    }
}
⚠️Never cleanWs() while debugging A wiped workspace destroys the evidence you need. Clean up only once the pipeline is stable — or use the patterns option to keep logs: cleanWs(patterns: [[pattern: '**/*.log', type: 'INCLUDE']]).

11.5 Failing loudly, but correctly

groovyResult control patterns
// A. Keep going, but remember that something went wrong
catchError(buildResult: 'UNSTABLE', stageResult: 'FAILURE') {
    sh 'npm run lint'
}

// B. Retry a flaky network step, then give up properly
retry(3) { sh 'docker pull node:20-alpine' }

// C. Retry with a growing delay (needs a script block)
script {
    def attempts = 3
    for (int i = 1; i <= attempts; i++) {
        try { sh 'curl -fsS https://registry.npmjs.org/'; break }
        catch (err) {
            if (i == attempts) { error "Registry unreachable after ${attempts} attempts" }
            sleep(time: i * 5, unit: 'SECONDS')
        }
    }
}

// D. Soft-fail a stage but keep the pipeline green (use with care!)
warnError('Lint found issues') { sh 'npm run lint' }   // Pipeline: Basic Steps 2.290+

11.6 ✍️ Jenkinsfiles v11 — the professional post

groovynodejs-app/Jenkinsfile — v11 (post block)
pipeline {
    agent any
    options {
        timestamps(); timeout(time: 30, unit: 'MINUTES')
        buildDiscarder(logRotator(numToKeepStr: '30', artifactNumToKeepStr: '5'))
        disableConcurrentBuilds()
    }
    environment { APP_NAME = 'nodejs-app'; IMAGE = '<user>/nodejs-app' }

    stages {
        stage('Checkout') { /* ...as before... */ }
        stage('Build')    { steps { dir(APP_NAME) { sh 'npm ci' } } }
        stage('Test')     { steps { dir(APP_NAME) { sh 'npm run test:junit' } } }
        stage('Docker Build') { steps { dir(APP_NAME) { script { app = docker.build("${IMAGE}:${env.GIT_SHA}", '--pull .') } } } }
        stage('Push') {
            when { branch 'main' }
            steps { script { docker.withRegistry('https://index.docker.io/v1/','dockerhub-creds') { app.push(env.GIT_SHA) } } }
        }
    }

    post {
        always {
            script {
                // readable build history
                currentBuild.description = "${env.GIT_SHA ?: 'unknown'}"
            }
            dir(APP_NAME) {
                junit testResults: 'reports/junit.xml', allowEmptyResults: true
                recordCoverage tools: [[parser: 'COBERTURA', pattern: 'coverage/cobertura-coverage.xml']],
                               sourceCodeRetention: 'LAST_BUILD'
            }
            archiveArtifacts artifacts: '**/reports/**,**/coverage/**', allowEmptyArchive: true
        }
        success  { echo "✅ ${APP_NAME} ${env.GIT_SHA} built and pushed" }
        unstable { echo "⚠️  Built, but quality gates were not met: ${env.BUILD_URL}" }
        failure  {
            script {
                def culprits = currentBuild.changeSets
                        .collectMany { it.items.collect { it.author.fullName } }.unique()
                echo "❌ FAILED — last commit by: ${culprits.join(', ') ?: 'unknown'}"
            }
        }
        fixed    { echo "🎉 Back to green after a failure" }
        regression { echo "🔥 Regression: this used to pass — investigate ${env.BUILD_URL}" }
        cleanup {
            sh 'docker image prune -f || true'
            cleanWs()
        }
    }
}

11.7 ✅ Checklist

  • I forced a failure and saw always, failure and cleanup all run in the right order.
  • Build history shows a readable description with the commit SHA.
  • Artifacts (JUnit XML, coverage) are downloadable from the build page.
  • Disk usage stopped growing between builds (cleanup works).

11.8 💬 Interview Q&A

Q1What goes in always vs cleanup?
always for things that are part of the result — publishing test reports, coverage and artifacts. cleanup for things that must happen no matter what, including if always itself throws: deleting temp files, stopping containers, pruning images. cleanup always runs last.
Q2How do you notify only when a build breaks — and only the person who broke it?
In post { failure { } } I read currentBuild.changeSets to extract the commit authors of this build, then message them (Slack DM or email). I use regression for "main was green, now it's broken" and fixed to close the loop.
Q3How do you stop a stage failing the whole pipeline?
catchError(buildResult:'UNSTABLE', stageResult:'FAILURE') — the stage is marked red, the build is marked unstable, and the pipeline continues. I use it for advisory checks (lint, optional scans), never for tests that guard a release.
Q4How do you stop Jenkins running out of disk?
Three layers: buildDiscarder(logRotator(...)) to cap build history, cleanWs() in post { cleanup } for workspaces, and regular docker image/container/builder prune — Docker layers are usually the biggest consumer on a CI machine.

11.10 Lab — the ordering experiment

🧪Lab 11.1 · Prove the post order yourself Run this on a pipeline both ways (success and forced failure) and read the console carefully.
groovyWhich conditions fire, and in what order?
pipeline {
    agent any
    parameters { booleanParam name: 'FAIL', defaultValue: false }
    stages {
        stage('work') {
            steps {
                script { if (params.FAIL) { error 'deliberate failure' } else { echo 'ok' } }
            }
        }
    }
    post {
        always      { echo 'ORDER 1: always' }
        changed     { echo 'ORDER 2: changed' }
        aborted     { echo 'ORDER 3: aborted' }
        regression  { echo 'ORDER 4: regression' }
        fixed       { echo 'ORDER 5: fixed' }
        success     { echo 'ORDER 6: success' }
        failure     { echo 'ORDER 6: failure' }
        unstable    { echo 'ORDER 6: unstable' }
        cleanup     { echo 'ORDER 7: cleanup (always last)' }
    }
}
Run it green, then with FAIL=true (regression), then green again (fixed). You now have first-hand evidence for the ordering table.

11.11 Notification payload design

💡Every alert should answer five questions What broke · Which commit/branch · Who is responsible · Where to look (deep link) · What to do next. If a message can't answer all five, people will ignore it.
groovyA well-formed failure message
post {
    failure {
        script {
            def c = currentBuild.changeSets.collectMany { it.items }.take(3)
            def who = c.collect { it.author.fullName }.unique().join(', ') ?: 'unknown'
            slackSend(channel: '#ci', color: 'danger', message: """
                :x: *${env.JOB_NAME}* #${env.BUILD_NUMBER} FAILED
                • Branch : ${env.BRANCH_NAME ?: 'n/a'}  • Commit: ${env.GIT_SHA ?: 'n/a'}
                • Stage  : ${env.STAGE_NAME}
                • Author : ${who}
                • <${env.BUILD_URL}|Console log>  • <${env.BUILD_URL}console|Full output>
            """.stripIndent().trim())
        }
    }
}

11.12 More interview Q&A

Q5How do you make sure a cleanup step always runs?
Put it in post { cleanup { } }, which runs after every other post condition — including if a step inside always throws. If the pipeline uses agent none, wrap it in node('label') { } so it has somewhere to execute.
Q6How do you attach build artifacts to a failure notification?
archiveArtifacts in post { always }, then link ${env.BUILD_URL}artifact/ in the message, or use emailext attachLog: true to include the console output. Deep links matter more than attachments — nobody downloads a file to find out what happened.
Q7What should never be in a post block?
Anything that can fail the build for a non-build reason. Notification and cleanup steps must be wrapped so that a Slack outage or a missing file can't turn a green build red.
Q8How do you record who approved or who broke a build for audits?
Capture the approver with submitterParameter on input and store it in currentBuild.description; derive the culprit from currentBuild.changeSets. Both end up in the build record, which I retain for the audit window with buildDiscarder.
